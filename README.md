# Express Cleaning Consult platform — implementation package

Read [ARCHITECTURE.md](ARCHITECTURE.md) first. This package implements the live request-first path plus a broader normalized schema, CRM/quote/dispatch/payment/voice endpoints, a four-step Next.js quote wizard, customer and staff portals, review follow-up job, and deployment configuration. The public quote flow can be deployed independently; the broader operations and payment platform is still gated by the approvals and provider tests below. No prices, guarantee of availability, or payment credentials were invented.

## Current business behavior

- Customers submit a free quote request. Staff review scope and approve a specific price, date and worker before taking a deposit or full payment.
- The seed catalog is based on the business handoff. Every seeded market is `request_only`; every service has `instant_eligible=false`; there are no active pricing rules. Payment requires an accepted quote and a staff-prepared booking.
- The optional `/quotes/preview` logic returns an estimate only after an owner-approved rate and market are enabled. The actual checkout remains quote/assignment gated; it does not silently turn a submitted date into a confirmed booking.
- The approved public contact details are `support@expresscleaningconsult.com` and `(281) 972-7712`. The private quote-notification inbox is `expressconsulting92@gmail.com`. Real served ZIPs, service policies, deposit percentage, taxes, and real-time crew capacity still require owner approval.
- Lead stages are derived from the latest service request, its quote, and booking. The 0–100 score is a deterministic work priority, not a predicted conversion rate. Staff may assign a permitted agent and record disposition/follow-up; stages cannot be manually forced.
- Every newly saved quote request atomically creates one `quote_review` staff task and one notification record. After returning the receipt, the API dispatches that notice through configured Resend credentials to `QUOTE_NOTIFICATION_TO`; request replays and provider retries use database and provider idempotency controls so the same receipt is not intentionally mailed twice. Provider-ambiguous sends stop in `needs_reconciliation` and are logged. The staff pipeline shows the receipt, contact details, service, location, task status, and notification status.
- Stripe is disabled by default. The hosted-invoice endpoint only runs when `STRIPE_PAYMENTS_MODE=test` is paired with a Stripe test/restricted-test key. It derives the amount from an accepted quote and prepared booking; only a signature-verified, duplicate-safe webhook can mark it paid or failed. Live mode additionally requires `STRIPE_LIVE_PAYMENTS_ENABLED=true` and must not be enabled until the business rules in this document are approved and sandbox tests pass.
- The before-and-after gallery renders only entries marked both `published` and `customerApproved` in `web/lib/gallery.ts`. It intentionally shows an honest empty state until original, approved project pairs are supplied.
- A completed recurring booking can start a service plan only after staff attest to customer approval. The plan is an operational schedule, not a Stripe subscription. Customer pause/resume/cancel requests wait for staff review and do not charge or cancel any external payment agreement.
- Booking completion queues one review email after the configured delay, only when a customer explicitly opted into review email. Set a verified HTTPS `REVIEW_URL`, `RESEND_API_KEY`, and a verified `MAIL_FROM_ADDRESS`. Uncertain send outcomes become `needs_reconciliation` and must be checked in Resend before any manual retry. Historical requests lacking consent are suppressed.

## Stack and local commands

- Web: Next.js 16 App Router, React 19, Tailwind 4, React Hook Form/Zod, Framer Motion. From `web`: `npm ci && npm run dev`.
- API: Laravel 13 on PHP 8.3, MySQL, Sanctum, Spatie Permission, Stripe PHP, Twilio PHP, Resend PHP, Dompdf. From `api`: `composer install`, copy `.env.example` to `.env`, set DB credentials, `php artisan key:generate`, `php artisan migrate --seed`, `php artisan serve --host=0.0.0.0 --port=8000`, and separately `php artisan queue:work database --queue=quote-notifications --tries=3` for quote notices.
- Approved campaigns require `php artisan schedule:work` (or a Railway cron service running `php artisan schedule:run` every minute). A delivery in `sending` after an uncertain SMS error requires manual provider reconciliation before retrying.
- Start MySQL separately. Browser-authenticated calls use the web service's same-origin `/api/*` and `/sanctum/*` rewrites to the Railway API, while the public quote stays stateless and calls the API origin directly. Keep `SESSION_DOMAIN` unset so the proxied cookie is host-only, include `www.expresscleaningconsult.com` in `SANCTUM_STATEFUL_DOMAINS`, allow the web origin in CORS, and require HTTPS. `GET /sanctum/csrf-cookie` precedes browser POST login.
- Test provider callbacks using Stripe CLI and Twilio's test environment; use their exact public webhook URLs and secrets.
- Staff access `/admin` for the pipeline and `/admin/calls` for the browser phone. Twilio inbound calls route to agents whose browser registered and heartbeated recently; production requires browser microphone permission, configured TwiML endpoints, and agent training. Customers access `/account` for booking history, invoice PDFs and recurring plan change requests. Older bookings created before the invoice migration have no invoice snapshot and need an explicit backfill.

| Service | Root | Image/process | Variables |
|---|---|---|---|

| Laravel API | `api/` | `api/Dockerfile`; Supervisor runs Apache, a database worker limited to `quote-notifications`, and the notification recovery loop | `APP_KEY`, `APP_URL`, `DB_*` or `DATABASE_URL`, `QUEUE_CONNECTION=database`, `SESSION_DOMAIN`, `SANCTUM_STATEFUL_DOMAINS`, `CORS_ALLOWED_ORIGINS`, `STRIPE_*`, `TWILIO_*`, `RESEND_API_KEY`, `MAIL_FROM_ADDRESS`, `QUOTE_NOTIFICATION_TO`, `STAFF_REVIEW_URL`, `REVIEW_URL`, `PORT=8080` |
| Scheduler | `api/` | same image, `php artisan schedule:work` or scheduled `schedule:run` | same DB settings; no public domain |
| MySQL | Railway managed database | managed | reference internal `MYSQLHOST`, `MYSQLPORT`, `MYSQLDATABASE`, `MYSQLUSER`, `MYSQLPASSWORD` into API/worker `DB_*` |

The API Railway config runs `php artisan migrate --force` as a pre-deploy command, before the new container receives traffic. It does not migrate on every process restart. Confirm the pre-deploy step succeeds, set up backups, and test a restore. Add an approved private object store before scope/photo uploads.

## Verification and remaining release gates

On September 30, 2026, a clean verification copy of the current web source passed `npm ci`, `npm run typecheck`, and a production `npm run build`. The in-place `web/node_modules` directory is locked by a local Windows/OneDrive process, so a second in-place `npm ci` returned `EBUSY`; no generated verification files were committed. PHP and Composer are not available in this workspace, so the changed Laravel migrations and feature suite were not rerun locally for this release; the Railway pre-deploy migration and application deployment must succeed before the new API behavior is considered live. The feature suite contains coverage for quote task/notification creation, idempotent request replay, queue recovery and provider-idempotency expiry, hosted-invoice authorization and idempotency, live-key rejection, and Stripe invoice webhook success, failure, duplicate, ordering, refund, amount/currency, and environment checks, but the code is not evidence that those tests ran here.

Production verification must separately record: the deployed web and API revisions; one new synthetic quote receipt; its single linked staff task; Resend provider acceptance and, if possible, inbox delivery; an idempotent replay that creates neither a second task nor a second notice; desktop/mobile and canonical-domain checks; and Stripe sandbox invoice success/failure/duplicate-event results. A Resend status of `sent` means the provider accepted the request, not that inbox delivery was independently observed. Do not enable live Stripe mode or issue a live invoice while these gates remain open.

The package does not include automatic subscription billing, worker self-service, media upload/review, email unsubscribe management, or a completed operations UI for all roles. Approved before/after photo pairs, verified customer reviews, payment timing/amount/refund rules, and the Square/Jobber reconciliation remain owner decisions. See [SETUP_AND_VERIFICATION.md](SETUP_AND_VERIFICATION.md) for configuration and verification procedures.
